## The Central Truth

Relatedness is a **system of design**, not a set of feelings.  
Feelings report; systems carry load. A network diagram shows every node with a function — your closest bonds need the same clarity.

You enter relatedness as a **teleios** person by design. Practice does not manufacture being; it aligns typed connection under load. Mapping does not invent your personhood. It stewards how whole persons relate without accident, fusion, or one-node collapse.

## Core Teaching

### 1) Relatedness defined

**Relatedness** = the patterned way persons are connected: type, purpose, access level, obligations, and review cadence.

Feeling-only relatedness: “we’re close because it feels close.”  
Design relatedness: “we are close *as* ______, therefore ______ is fitting.”

Feelings matter as **Emotional** attribute signals. They do not rewrite ontology. Mental clarity names type; Conative follow-through keeps access honest; Behavioral presence matches the edge you claimed.

### 2) Teleios grammar (non-negotiable for Course 09)

In this canon, teleios / perfect = **design-state / full development** — the human as designed, not a flawless networking record.

| Illegal relatedness grammar | Teleios relatedness grammar |
|-----------------------------|-----------------------------|
| Map myself into worth | Map because I already am a person |
| Collect nodes to feel complete | Steward edges as a better whole |
| Accidental intimacy as identity | Typed intimacy as stewardship |
| One person as entire stack | Distributed load under design |
| Practice invents my being | Practice reveals and aligns relatedness |

If your private sentences still sound like the left column, you will weaponize Weeks 2–6 as a worth-factory or a fusion project.

### 3) Ratiocination

- Premise 1: What a person *is* (teleios by design) precedes what a bond *practices*.
- Premise 2: Feeling-only relatedness treats closeness as weather and persons as mood utilities.
- Premise 3: Design presents typed bonds with fitting access, obligation, and review.
- Conclusion: Relatedness frameworks must start from teleios + better whole, or mapping manufactures anxiety and type-smuggling even when “connected.”

### 4) Map fields (required)

For each of three closest bonds:

| Field | Question |
|-------|----------|
| Type | Marriage / family / friend / work / mentor? |
| Function | What load is this bond designed to carry? |
| Access | What intimacy/time/info is fitting? |
| Obligation | What do I owe; what do they owe? |
| Accident risk | Where is this undefined? |
| Ontology check | Am I using this node to complete my being? |

### 5) Network map

Draw nodes (persons) and edges (bond types). Mark:

- Overloaded edges (too much function for type)  
- Ghost edges (access without purpose)  
- Missing edges (isolation where kinship/friendship should exist)  
- Fusion edges (access that denies the other’s agency or your own teleios)

Analogy: every node has a function. When one node is forced to be router, server, and battery, the system fails. Stop asking one person to be your entire stack. You are teleios; they are teleios; the stack is design, not a prosthetic self.

### 6) Relatedness Rule

Template:

> I am teleios by design; relatedness does not invent me.  
> I will not expand access beyond type. I will not demand of ______ what belongs to ______.  
> Accidental relatedness ends when I name type and keep it.  
> Better whole only — no node completes my ontology.

Witness this rule. Private mythology loves unshared maps.

### 7) Accidental zones (common)

- Work confessor / emotional spouse  
- Friend treated as unpaid therapist without consent  
- Parent still governing adult marriage  
- Romance without named covenant track  
- Mentoring that smuggles romantic or parental load  

For one zone, write four cost columns: Body · Household/friendship · Calling · Inner life.

### 8) Faculties under relatedness load

| Faculty / attribute | Stewardship move |
|---------------------|------------------|
| Mental | Name type without fog |
| Emotional | Feel closeness without rewriting type |
| Conative | Keep access promises |
| Behavioral | Show up at fitting cadence |
| Affective / desire | Desire does not authorize ghost edges |

Course 07 self-command still applies: you do not outsource will to a favorite node.

### 9) Continuity: Course 08 → 09 → 10

Course 08: heart rails (what a relationship is; trust; communication; repair).  
Course 09 Week 1: the network those rails run on.  
Course 10: covenant-grade intensity on governed systems — not intensity on accident.

### 10) What this week is not

Not cold charting that avoids care.  
Not type-rigidity used to refuse honor.  
Not anti-feeling. It is anti-**feeling-as-ontology**.  
Not permission to isolate under “design” branding.

### 11) Language discipline

- “We’re close, so everything is allowed.” → “Closeness has a type; access matches type.”  
- “I need them to feel like a real person.” → “I am teleios; they support, they do not invent me.”  
- “Maps are unromantic.” → “Unmapped romance is how overload and contempt arrive.”

### 12) Continuity into Week 2

Maps without fences collapse under pressure. Week 2 installs boundaries and honor so typed edges can hold without hostility or fusion.

## Case Contrasts

### Case A — Feeling map
Mira ranks people by chemistry; types blur; one friend becomes unpaid spouse-therapist; burnout and quiet contempt. She maps moods, not design. Fruit: chronic confusion, ghost edges everywhere.

### Case B — Rigid map without honor
Eli uses types to avoid care. “You’re only a colleague” becomes an excuse for cruelty. Chart without teleios dignity. Fruit: isolation with vocabulary, no better-whole generosity.

### Case C — Design map from teleios
Sam draws the network, cuts ghost access, writes a Relatedness Rule that names teleios and better whole, keeps care inside type, and refuses one-node collapse. Fruit: clarity without coldness; load distributed; heart rails from Course 08 finally have a place to run.
