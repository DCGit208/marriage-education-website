# Week 1: Relatedness Framework
## Design System — Not a Set of Feelings

> **Week 1 of 6** | 8–10 hours | Framework  
> **Sources:** Course 08 · network design · better whole

---

## The Central Truth

Relatedness is a **system of design**, not a set of feelings.  
Feelings report; systems carry load. A network diagram shows every node with a function — your closest bonds need the same clarity.

---

## Week Overview

### Core Question
How is relatedness a design system, not a feeling set?

### Key Insight
Accidental relatedness is how good people become chronically confused. Mapping type, function, access, and load prevents type-smuggling (treating friends like spouses, spouses like parents, colleagues like confessors).

### Learning Outcomes
- Map three closest relationships by design type  
- Identify one accidental relatedness zone  
- Define a Relatedness Rule  
- Draw a relationship network map  
- Pass a Relatedness Framework Audit  

---

## Core Teaching

### 1) Relatedness defined

**Relatedness** = the patterned way persons are connected: type, purpose, access level, obligations, and review cadence.

Feeling-only relatedness: “we’re close because it feels close.”  
Design relatedness: “we are close *as* ______, therefore ______ is fitting.”

### 2) Map fields (required)

For each of three closest bonds:

| Field | Question |
|-------|----------|
| Type | Marriage / family / friend / work / mentor? |
| Function | What load is this bond designed to carry? |
| Access | What intimacy/time/info is fitting? |
| Obligation | What do I owe; what do they owe? |
| Accident risk | Where is this undefined? |

### 3) Network map

Draw nodes (persons) and edges (bond types). Mark:

- Overloaded edges (too much function for type)  
- Ghost edges (access without purpose)  
- Missing edges (isolation where kinship/friendship should exist)  

### 4) Relatedness Rule

Template:

> I will not expand access beyond type. I will not demand of ______ what belongs to ______. Accidental relatedness ends when I name type and keep it.

### 5) Better whole

Your network is not a prosthetic self. Nodes support; they do not complete ontology. Course 07–08 still apply: self-command and repair remain yours.

### 6) Analogy: network diagram

Every node has a function. When one node is forced to be router, server, and battery, the system fails. Stop asking one person to be your entire stack.

### 7) Accidental zones (common)

- Work confessor / emotional spouse  
- Friend treated as unpaid therapist without consent  
- Parent still governing adult marriage  
- Romance without named covenant track  

### 8) Continuity

Week 2 installs fences (boundaries) so the map can hold under pressure.
